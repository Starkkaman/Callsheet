# File map

- `README.md`: what Callsheet is, status, install steps, dev commands.
- `CLAUDE.md`: project rules (read-only, offline, relative URLs), design source, test commands.
- `filemap.md`: this file.
- `.gitignore`: Python caches, venvs, logs, local screenshots.
- `repository.yaml`: Home Assistant app repository (name, url, maintainer).
- `callsheet/config.yaml`: app manifest (slug callsheet, ingress on 8099, sidebar icon/title, options `writer_local_url`/`writer_local_model`; 0.5.1: `homeassistant_api: true` for phone notifications; `backup_exclude` for `signal-cli`; 0.6.0: `map` share/media read-only (Obsidian vault) and `backup_exclude` also `index.db*`).
- `callsheet/Dockerfile`: image from the HA base-python image; adds tzdata, signal-cli with libsignal and a headless Java 25 (Alpine community, 0.5.1; `JAVA_OPTS`) and the pinned `anthropic` SDK; copies app/ and run.sh.
- `callsheet/run.sh`: container start script (bashio log line, starts server.py on 8099).
- `callsheet/DOCS.md`: user documentation shown in Home Assistant: features, Google Cloud client setup, connecting an account, Slack setup (manifest, admin approval), doesn't-need-a-reply, time format, AI writer (writing profiles, Claude, local model, app options), data, troubleshooting; Signal; phone notifications; 0.6.0: Know me (the five steps, Drive and Obsidian setup) and Chat (model, tool use, server slot, what is sent), your data. 0.8.0: See everything.
- `callsheet/CHANGELOG.md`: release notes per version.
- `callsheet/app/server.py`: stdlib web server (thin): static files (index.html filled in with the app version, `?v=` asset URLs, ETag and 304 for the page, app.css and app.js), `api/*` routing, client allowlist, X-Callsheet header, 64 KB JSON bodies, JSON errors (409 for conflicts), attachment downloads; refuses to start if the database can't be opened.
- `callsheet/app/api.py`: `App`: route table and handlers for the JSON API (brief, state with the app version `APP_VERSION`, Google client, areas, accounts, VIPs, settings, sync, writer and writing profiles, Slack, suppression rules, writer evaluation; 0.5.0: `api/memory` (view, save, reset, notes from brief items) and the brief's possible events and note marks; 0.5.1: `api/push`, `api/push/targets`, `api/push/test`; Signal routes from `signal_api`; 0.6.0: `api/index/*`, `api/profile/*` and `api/chat/*` in their own sections; a chat model change forgets the chat's JSON fallback); seeds the local writer from `options.json`. 0.6.1: `api/writer/presets`, `api/writer/models` (the preset model check against /v1/models), the brief's `writing` state, Refresh in the background for a slow preset.
- `callsheet/app/store.py`: SQLite storage (`$CALLSHEET_DATA/callsheet.db`, 0600): schema version (additive upgrades, `StoreError` instead of a fresh DB), settings defaults and validation, phone notification settings and state (0.5.1), areas, accounts and tokens, VIPs, writer settings and keys, evaluation settings, last sync, last writer run, cached brief; Slack workspaces (token, ignore list, read state), writing profiles, suppression rules, new-since keys, brief row refs; 0.5.1 Signal: meta (masked number, area, ignored chats, salt), chats, messages (30-day retention for live ones, imported kept), import staging. 0.6.1: writer presets, the call kind mapping and `reload_fast` (validation in presets.py).
- `callsheet/app/google.py`: Google network code: OAuth and read-only Gmail/Calendar calls behind a (method, URL) allowlist; env overrides for tests.
- `callsheet/app/github.py`: 0.7.0 GitHub network code: read-only (method, URL) allowlist (GET `/user/repos`, `/repos/{o}/{r}`, commits, issues, pulls), no redirects, pagination, ETag, rate limit, token check; env override for tests.
- `callsheet/app/slack.py`: Slack network code (0.4.0): read-method allowlist, manifest and create URL, token check, per-sync client with Retry-After, backoff and a request cap, the read of one workspace (DMs, channels, threads, mentions) and its saved state.
- `callsheet/app/signalcli.py`: Signal (0.5.1): signal-cli as a linked device, JSON-RPC over stdio with a method allow-list (startLink, finishLink, subscribeReceive, unsubscribeReceive, listAccounts, listContacts, listGroups); `SignalService`: the process (`/data/signal-cli` 0700, own session, clean stop, restart with backoff), link flow (QR, finishLink as "Callsheet", expiry), receive → envelopes to stored messages (mentions, quotes, edits, deletes; salted ids), unlink, status with the masked number; scrubbed stderr.
- `callsheet/app/signal_api.py`: the `api/signal` routes (0.5.1): status, settings (area, ignored chats), link/cancel/unlink, the chunked history upload (start, raw chunks, finish), pick chats to import, discard, delete imported history.
- `callsheet/app/signal_import.py`: streamed parser for Signal Desktop's `main.jsonl` export and signal-export's `data.json` (0.5.1): keeps text, names and times only; keys and phone numbers are skipped.
- `callsheet/app/qr.py`: QR code as a server-side SVG (one path) for the Signal link code, using the vendored qrcodegen.
- `callsheet/app/vendor/qrcodegen.py`: Nayuki QR Code generator v1.8.0 (MIT), vendored unchanged (sha256 checked by the tests); `vendor/__init__.py` marks the package.
- `callsheet/app/writer.py`: the AI writer: minimised payload, `compose_system` (profile texts, then the fixed safety block), local system = composed prompt + schema + `LOCAL_RULE` (the evaluated 0.3.5 shape), the owner's notes in their own `<notes>` block after the facts with the fixed `NOTES_RULE` only when there are notes (0.5.0), per-request output schema (replies keyed by row id, area summaries, Top of the day), HTML to text, quoted history and signature stripping, decision/payment post-check, local options (thinking, max tokens, context fit, timeout, retry while loading), Claude via the `anthropic` SDK (lazy import), local OpenAI-compatible server via urllib (`/models`, `/chat/completions` only), plain-word errors. 0.6.1: `LocalTimeout`, effort and template kwargs in the body only when set, `local_models`, wall/server time per answer.
- `callsheet/app/presets.py`: 0.6.1 writer presets per call time (pure): the built-in Fast preset (= writer.local), the owner's presets and their validation, the call kind → preset mapping (morning, midday, afternoon, refresh; default Fast), request options per preset, the Careful (Swift) suggestion, the reload body, the Heads up and writing texts.
- `callsheet/app/evaluate.py`: owner-run writer evaluation with contenders (0.5.0): 2 to 4 contenders (local or Claude model, thinking, effort, budget, sampling, writing profile) validated here, migration of the old Gemma/Qwen settings, each-vs-each or baseline pairings, refusal checks (call-time window, sync or run busy, setup problems), builds the writer input like a sync without storing anything live, per-contender requests (local with the loading retry, Claude via the SDK) and the reload of the everyday model, per-contender metrics, `writer-eval/<UTC time>/` files (0700/0600, last 5 kept, old runs still readable), blind A/B pairs seeded per run, choices with wins/losses/ties and the NDJSON export; the server's model list for the form.
- `callsheet/app/evalscore.py`: pure draft scorer for the evaluation (ported from the replay harness, object-keyed replies): commitments, placeholders used/needed, invented answers, answer-shape check.
- `callsheet/app/oauth.py`: account connection flow: state + PKCE in memory (15 min), auth URL, paste-back parsing, code exchange, plain-word errors.
- `callsheet/app/index.py`: 0.6.0 Know me index: `/data/index.db` (0600) with items + FTS5, idempotent upserts, planted-instruction flags (`instr`, hashes only; backfill), cursors, search/get/stats, delete per source/account, wipe.
