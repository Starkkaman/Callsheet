# File map

- `README.md`: what Callsheet is, status, install steps, dev commands.
- `CLAUDE.md`: project rules (read-only, offline, relative URLs), design source, test commands.
- `filemap.md`: this file.
- `.gitignore`: Python caches, venvs, logs, local screenshots.
- `repository.yaml`: Home Assistant app repository (name, url, maintainer).
- `callsheet/config.yaml`: app manifest (slug callsheet, 0.4.1, ingress on 8099, sidebar icon/title, options `writer_local_url`/`writer_local_model`).
- `callsheet/Dockerfile`: image from the HA base-python image; adds tzdata and the pinned `anthropic` SDK; copies app/ and run.sh.
- `callsheet/run.sh`: container start script (bashio log line, starts server.py on 8099).
- `callsheet/DOCS.md`: user documentation shown in Home Assistant: features, Google Cloud client setup, connecting an account, Slack setup (manifest, admin approval), doesn't-need-a-reply, time format, AI writer (writing profiles, Claude, local model, app options), data, troubleshooting.
- `callsheet/CHANGELOG.md`: release notes per version.
- `callsheet/app/server.py`: stdlib web server (thin): static files (index.html filled in with the app version, `?v=` asset URLs, ETag and 304 for the page, app.css and app.js), `api/*` routing, client allowlist, X-Callsheet header, 64 KB JSON bodies, JSON errors (409 for conflicts), attachment downloads; refuses to start if the database can't be opened.
- `callsheet/app/api.py`: `App`: route table and handlers for the JSON API (brief, state with the app version `APP_VERSION`, Google client, areas, accounts, VIPs, settings, sync, writer and writing profiles, Slack, suppression rules, writer evaluation; 0.5.0: `api/memory` (view, save, reset, notes from brief items) and the brief's possible events and note marks); seeds the local writer from `options.json`.
- `callsheet/app/store.py`: SQLite storage (`$CALLSHEET_DATA/callsheet.db`, 0600): schema version (additive upgrades, `StoreError` instead of a fresh DB), settings defaults and validation, areas, accounts and tokens, VIPs, writer settings and keys, evaluation settings, last sync, last writer run, cached brief; Slack workspaces (token, ignore list, read state), writing profiles, suppression rules, new-since keys, brief row refs.
- `callsheet/app/google.py`: Google network code: OAuth and read-only Gmail/Calendar calls behind a (method, URL) allowlist; env overrides for tests.
- `callsheet/app/slack.py`: Slack network code (0.4.0): read-method allowlist, manifest and create URL, token check, per-sync client with Retry-After, backoff and a request cap, the read of one workspace (DMs, channels, threads, mentions) and its saved state.
- `callsheet/app/writer.py`: the AI writer: minimised payload, `compose_system` (profile texts, then the fixed safety block), local system = composed prompt + schema + `LOCAL_RULE` (the evaluated 0.3.5 shape), the owner's notes in their own `<notes>` block after the facts with the fixed `NOTES_RULE` only when there are notes (0.5.0), per-request output schema (replies keyed by row id, area summaries, Top of the day), HTML to text, quoted history and signature stripping, decision/payment post-check, local options (thinking, max tokens, context fit, timeout, retry while loading), Claude via the `anthropic` SDK (lazy import), local OpenAI-compatible server via urllib (`/models`, `/chat/completions` only), plain-word errors.
- `callsheet/app/evaluate.py`: owner-run writer evaluation (0.3.3): refusal checks (call-time window, sync or run busy, no local server), builds the writer input like a sync without storing anything live, G0 / Q-low / Q-med requests and the Gemma reload to the local server, per-setup metrics, `writer-eval/<UTC time>/` files (0700/0600, last 5 kept), blind A/B pairs seeded per run, choices and the NDJSON export.
- `callsheet/app/evalscore.py`: pure draft scorer for the evaluation (ported from the replay harness, object-keyed replies): commitments, placeholders used/needed, invented answers, answer-shape check.
- `callsheet/app/oauth.py`: account connection flow: state + PKCE in memory (15 min), auth URL, paste-back parsing, code exchange, plain-word errors.
- `callsheet/app/rules.py`: pure rules: schedule rows, clashes, all-day, needs-a-reply reasons (Gmail categories, suppression), Slack rows and Heads up, rules-based Top of the day, 12h/24h display times, call times, brief composition.
- `callsheet/app/facts.py`: pure facts for the writer (0.4.1): waiting days, unanswered messages and follow-ups, deadlines found in the last message, clash pairs in time order, oldest wait, due today, counts; the content of the `<facts>` block; the rows' wait wording for the page (`row_wait`).
- `callsheet/app/memory.py`: the owner's notes to Callsheet (0.5.0): `$CALLSHEET_DATA/memory.md` (0600; sections Notes, Profile, Answers; one `###` entry per note with `- key: value` metadata), parse/validate, add/edit/delete/save/reset, the notes relevant to a brief (`relevant`, about 1,500 characters), metadata for a note on a brief item.
- `callsheet/app/dates.py`: possible events (0.5.0): dates and times proposed in a reply row's latest message (deterministic, per sentence; deadlines via `facts.due`), skipped when already on the calendar, titles, the Add to calendar link (Google Calendar template URL with ctz and authuser) and the page's display fields.
- `callsheet/app/sync.py`: one sync over all accounts (token refresh, per-account errors; the read path is shared with the writer evaluation), flags rows whose latest incoming message states a decision (`claim`) and their wait wording (`wait`), reads the calendar 14 days ahead for the possible events (only today's go into the schedule), picks the relevant notes for the writer input (also used by the evaluation), caches the brief, then runs the AI writer when on (summary, suggestions, or a Heads up line); counts-only log lines.
- `callsheet/app/scheduler.py`: background thread: sync at call times in the configured time zone, and at start-up when stale.
- `callsheet/app/sample_brief.json`: sample Daily Brief data (v3 example, `"sample": true`, all `sections` "sample").
- `callsheet/app/static/index.html`: page shell (a template: `{{version}}` in the version meta and the asset URLs): compact header (wordmark, date, last refreshed, Refresh/Setup/Look), the update notice, main, and `<template id="icons">` (inline SVG glyphs cloned by app.js, incl. the lock).
- `callsheet/app/static/app.css`: theme tokens (from themes.css) + reason-dot colours + tabbed brief styles (`.bv`: tab bar, rows, side panel, briefing, agenda timeline, areas columns, menu and toast layer); setup additions (Slack section and connect steps, ignore-channel chips, writing instructions with the locked box, never-reply rules list); phone under 700px (bottom tab bar, full-screen panel).
- `callsheet/app/static/app.js`: fetches `api/brief`, renders the tabbed brief (Briefing, Replies, Agenda, Areas; Tasks reserved) with the detail panel (Suggested reply with Copy; the sender's-claim note and the list's "!"), notepad menu (`api/suppress` + Undo, local Dismiss, Note for Callsheet: `api/memory/notes`), Agenda's Possible events (Add to calendar link), Done (`api/done` + Undo), last tab in localStorage; look/mode; setup steps: About you (time format), Areas (Google accounts, Slack connect/ignore channels/disconnect, read chips), VIPs (never-reply rules, the brief's "Manage"), Delivery (Writer block, writing instructions: profiles and their five sections, Memory: the memory file's editor and Clear memory); the Writer evaluation page (#eval); the version check (page meta against `api/state`) and its Reload notice.
- `callsheet/app/static/fonts/`: Londrina Solid, Jost (ttf), IBM Plex Sans, Atkinson Hyperlegible (woff2, latin).
- `callsheet/app/static/fonts/OFL-*.txt`: SIL OFL 1.1 licence text for each font family.
- `tests/test_server.py`: stdlib unittest: routes, headers, versioned assets and ETag/304, app version equals config.yaml, 403 for other clients, relative and offline URLs, no HTML sinks in app.js, the icon template.
- `tests/fake_google.py`: fake Google HTTP server for tests (token/revoke with PKCE checks, Gmail and Calendar reads; records requests).
- `tests/test_api_google.py`: API end to end against the fake Google: settings, areas, VIPs, connect flow and its errors, sync, live brief, GET-only, secrets never returned.
- `tests/test_google_client.py`: Google client allowlist (GET only to Gmail/Calendar, POST only to token/revoke); only google.py opens connections.
- `tests/test_rules.py`: schedule and reply rules, call times and days off, scheduler, brief composition.
- `tests/fake_ai.py`: fake Anthropic API and fake OpenAI-compatible local server (llama.cpp-like reasoning_content and timings, "Loading model" 500s, dropped connections) for tests; record requests.
- `tests/test_writer.py`: AI writer end to end against the fakes (Claude tests skip without the `anthropic` package): settings, payload minimisation, injection, errors, local JSON mode, fallback, app options seeding.
- `tests/test_writer_local.py`: writer fixes (0.3.2) against the fakes: per-request schema (replies keyed by row id, both writers, legacy array), quote and signature stripping, decision/payment post-check and its warning, thinking off/on request body, retry while the model loads, answer rescued from the thinking channel, counts-only logs, local settings validation.
- `tests/test_eval.py`: writer evaluation against fake Google and a fake local server that answers per model id (and 503 "Loading model"): toggle off, call-time window, concurrency, live brief unchanged, request order and bodies, storage and retention, metrics, blind pairs, choices, export.
- `tests/test_release_041.py`: 0.4.1: facts (unanswered messages and follow-ups with the SENT label and Slack, waiting days across time zones, deadline parsing, clash order, oldest wait, counts), the facts block after the data and its escaping (a fake facts block in mail stays data), the fixed facts sentence with the 0.4.0 fixed parts byte-identical, the wait texts, Default = 0.4.0's texts + the new lead sentence, a 0.4.0 store keeps owner profiles.
- `tests/test_release_050_memory.py`: 0.5.0 memory: file CRUD and 0600, validation, relevance (email, name, domain, topic, area, general, public domains, cap, order), `api/memory` routes, the `<notes>` block after the facts (escaped; fake notes in mail stay data), `NOTES_RULE` only with notes and the fixed parts unchanged, local, Claude and evaluation inputs.

- `tests/test_inbound_claim.py`: 0.4.1 sender's-claim check: the row flag for mail (subject/snippet, reply
- `tests/test_wait_text.py`: 0.4.1 wait text on reply rows: `facts.row_wait` (same rule as the facts block, owner's time zone, Slack), stored and served with or without the writer (no text kept), app.js shows it via h() in place of the age.
