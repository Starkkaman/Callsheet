# File map

- `README.md`: what Callsheet is, status, install steps, dev commands.
- `CLAUDE.md`: project rules (read-only, offline, relative URLs), design source, test commands.
- `filemap.md`: this file.
- `.gitignore`: Python caches, venvs, logs, local screenshots.
- `repository.yaml`: Home Assistant app repository (name, url, maintainer).
- `callsheet/config.yaml`: app manifest (slug callsheet, ingress on 8099, sidebar icon/title, options `writer_local_url`/`writer_local_model`; 0.5.1: `homeassistant_api: true` for phone notifications; `backup_exclude` for `signal-cli`; 0.6.0: `map` share/media read-only (Obsidian vault) and `backup_exclude` also `index.db*`).
- `callsheet/Dockerfile`: image from the HA base-python image; adds tzdata, signal-cli with libsignal and a headless Java 25 (Alpine community, 0.5.1; `JAVA_OPTS`) and the pinned `anthropic` SDK; copies app/ and run.sh.
- `callsheet/run.sh`: container start script (bashio log line, starts server.py on 8099).
- `callsheet/DOCS.md`: user documentation shown in Home Assistant: features, Google Cloud client setup, connecting an account, Slack setup (manifest, admin approval), doesn't-need-a-reply, time format, AI writer (writing profiles, Claude, local model, app options), data, troubleshooting; Signal; phone notifications; 0.6.0: Know me (the five steps, Drive and Obsidian setup) and Chat (model, tool use, server slot, what is sent), your data. 0.8.0: See everything.
- `callsheet/CHANGELOG.md`: release notes per version.
- `callsheet/app/server.py`: stdlib web server (thin): static files (index.html filled in with the app version, `?v=` asset URLs, ETag and 304 for the page, app.css and app.js), `api/*` routing, client allowlist, X-Callsheet header, 64 KB JSON bodies, JSON errors (409 for conflicts), attachment downloads; refuses to start if the database can't be opened.
- `callsheet/app/api.py`: `App`: route table and handlers for the JSON API (brief, state with the app version `APP_VERSION`, Google client, areas, accounts, VIPs, settings, sync, writer and writing profiles, Slack, suppression rules, writer evaluation; 0.5.0: `api/memory` (view, save, reset, notes from brief items) and the brief's possible events and note marks; 0.5.1: `api/push`, `api/push/targets`, `api/push/test`; Signal routes from `signal_api`; 0.6.0: `api/index/*`, `api/profile/*` and `api/chat/*` in their own sections; a chat model change forgets the chat's JSON fallback); seeds the local writer from `options.json`. 0.6.1: `api/writer/presets`, `api/writer/models` (the preset model check against /v1/models), the brief's `writing` state, Refresh in the background for a slow preset. 0.8.4: `api/sorting*` routes, `state.sorting`, the brief's `sorting` block when sorting is on. 0.8.5: `api/sorting/learned`, `api/sorting/forget`, Done teaches the sorter (`learn_done`).
- `callsheet/app/store.py`: SQLite storage (`$CALLSHEET_DATA/callsheet.db`, 0600): schema version (additive upgrades, `StoreError` instead of a fresh DB), settings defaults and validation, phone notification settings and state (0.5.1), areas, accounts and tokens, VIPs, writer settings and keys, evaluation settings, last sync, last writer run, cached brief; Slack workspaces (token, ignore list, read state), writing profiles, suppression rules, new-since keys, brief row refs; 0.5.1 Signal: meta (masked number, area, ignored chats, salt), chats, messages (30-day retention for live ones, imported kept), import staging. 0.6.1: writer presets, the call kind mapping and `reload_fast` (validation in presets.py).
